# 场景① 三维空间感升级 · 方案验证设计

> 2026-07-16 ｜ 目标：把场景①（index.html）从「二维平面布局」升级为概念稿中的「三维环形空间」，三条技术路线各出一版可对比原型，验收后再定迁移路线。

## 背景与差距

概念稿（两张：VR 视角环形试衣间 / AI Fitting Room 2.0）的空间感来自五点，当前 POC 均缺失或仅有平面模拟：

| 维度 | 概念稿 | 当前 POC |
|---|---|---|
| 空间结构 | 环形房间，衣服沿弧线环绕、近大远小、朝向圆心 | 左右两列贴屏平排 |
| 面板朝向 | 玻璃面板 rotateY 内倾，悬浮在人物两侧空间中 | 全部 0° 正对屏幕 |
| 纵深分层 | 前景面板→中景光柱→背景衣墙/穹顶，背景景深模糊 | 渐变背景 + 假透视网格 |
| 运动视差 | 空间层次随视点微移产生视差 | 无相机运动 |
| 地面反射 | 亮面地板，多物体倒影 | 仅人物一个倒影 |

## 决策记录

- **范围**：本轮只做场景①；场景②③待验收后按同一空间语言迁移。
- **形式**：三条路线各出一版完整功能原型，放仓库内 `3d-lab/`，用户验收效果后再定正式迁移路线。
- **约束**：延续 README 原则 —— 离线可用、零 License 问题；1920×1080 固定舞台整体缩放不变。

## 三个版本的共同要求

- 基于现有场景①完整功能：选衣联动面板数据、拖拽 360° 旋转、收藏漏斗（试穿间托盘 / CTA 置灰逻辑）、toast、步骤指示、`?still` `?fav=` `?sel=` URL 参数全部保留。
- 同一套素材与文案，保证对比公平。
- CTA 仍跳 `../scene2.html?fav=…&sel=…`，业务流程不断。
- 动画只用 transform/opacity（GPU 加速），kiosk 长时运行不掉帧。

## 各版本的空间感要点

### 方案A：纯 CSS 3D 场景化（a-css3d.html）

- 舞台加 `perspective`（约 1400–1800px），场景组织为 `preserve-3d` 的「房间」容器。
- 左右玻璃面板 `rotateY` 内倾 10–14°，`translateZ` 抬到前景层。
- 6 件衣服改环形排布：`rotateY(±θ) translateZ(-r)`，近大远小、朝向圆心。
- 地面改真 3D 平面（`rotateX(~90°)` 大平面）+ 环形灯带 + 亮面反射。
- 穹顶圆环压入背景深处（`translateZ` 负值）+ 轻微 blur 模拟景深。
- 房间容器缓慢相机漂移（±1.5° 摆动）+ 指针视差，静止画面也有空间感。
- 注意：`backdrop-filter` 元素必须是 3D 变换树的叶子节点，避免强制扁平化。

### 方案B：three.js + CSS3DRenderer 混合（b-threejs.html）

- WebGLRenderer：环形房间几何（反射地板、穹顶灯环、体积感光柱、上升粒子）。
- CSS3DRenderer：现有 HTML 玻璃面板作为 CSS3DObject 挂进场景，保持 DOM 交互。
- 真透视相机缓慢环绕漂移 + 指针视差。
- three.js 下载到 `vendor/three/` 本地引用（MIT License，符合零 License 风险）。
- 已知风险：双渲染器遮挡需手动处理；DOM 面板在 3D 变换下的文字清晰度需验证。

### 方案C：2.5D 分层视差（c-parallax.html）

- 面板保持贴屏（不做 3D 倾斜）。
- 背景拆多层：穹顶 / 衣墙 / 灯环 / 地板，随时间与指针做不同速率漂移缩放。
- 作为最低成本参照组，衡量「只靠氛围」能到什么程度。
